A simple plan for our website: how we would build it, where it would live, and which web address people would type in.

Core Launch Team • October 2026

What we will cover

Direction

Overall: we have a clear website direction, with room for feedback and refinement as we move forward.

A website our volunteers can look after

We would use WordPress, one of the most common tools for building websites, with Elementor Pro, a visual editor that makes pages easier to maintain.

The website

Easy to update

Page layouts stay in place. A new volunteer can change the text and photos without knowing any code.

Less need for one specific person who knows how it works.

The website

Locked design

Settings can protect the look of the site, so editing a page cannot accidentally break its design.

The site keeps looking the way we intend.

Sermons and audio

Podcasts through Podbean

Sermon audio would be hosted on Podbean, the same service newlife.nu already uses successfully.

Audio files stay off our website, so pages load faster.

Sermons and audio

Proven, not new

Because the setup already works for our existing church site, we know how it behaves and what it costs.

Fewer surprises for the team.

Recommendation

Recommended direction: Continue with WordPress and Elementor Pro, while keeping the setup simple and easy for volunteers to maintain.

Where the website lives, and how it stays fast

Every website is stored on a computer somewhere. That is called hosting. We would choose a company in Sweden, so the site is close to our visitors and is easier to support locally.

Hosting option

HostUp

Modern security that scans for harmful files in real time. Good performance for the price.

A strong choice if budget is the main concern.

Hosting option

Oderland

An established Swedish provider. Each customer gets a separate account, and the site is backed up automatically.

A safe, well-known choice if we want extra peace of mind.

Speed and protection

Copies close to visitors

Cloudflare keeps copies of our pages at locations across Sweden, so they load quickly for everyone.

Visitors get fast pages, and we pay nothing for the basic version.

Speed and protection

A shield in front of the site

Cloudflare hides the real location of our server, which makes common attacks much harder.

Basic protection that works in the background.

Recommendation

Recommended direction: Use a Swedish hosting partner and pair it with Cloudflare for speed and basic protection.

A free option we considered

We could also build a simple site with GitHub Pages. It costs nothing, and modern AI tools can help write the pages.

Good points

No hosting bill

The site is free to run, and it is fast because it is only simple pages.

Good for a basic information site.

Good points

Help from AI tools

Someone with basic computer skills could create and change pages with AI assistance.

Less technical know-how needed to start.

The catch

This option cannot store information behind a login or keep a database of people, events, or sign-ups. Volunteers without technical skills would not be able to update the site easily. It is fine for a basic page, but not for the kind of church site we want to grow.

Recommendation

Recommended direction: Keep GitHub Pages out of the main church website plan and focus on a managed hosting solution instead.

Our web address plan

Our pastor has chosen the main network page. Each location still has its own site, linked from the front page.

Considered

One address for each location

For example newlifegoteborg.se, newlifegoteborg.nu, or newlifegoteborg.com. Göteborg gets its own website, built just for the local community.

Easy to remember and clearly local.

Chosen

One main address for the whole church

For example newlifechurch.se. The front page welcomes people and sends them to Alvik, South, or Göteborg depending on where they belong.

Shows that we are one church in several places.

Decided

We will build one main church network page at newlifechurch.se. It introduces the church and links to each location's own website, if needed. Suggestions are welcome as we finalise the details.

Decided

Decided: Our pastor has chosen Option B. The main church page is the front door, and each location's site is linked from there.
